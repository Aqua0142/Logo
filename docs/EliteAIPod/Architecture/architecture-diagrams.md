## Blood Work Data Flow — End to End

Traces blood work data from Lab Technician form submission through API validation and encrypted storage, then through the patient results query that joins reference ranges and computes out-of-range flags, to the conditional-formatted table rendered in the patient's browser.
```mermaid
flowchart LR
    LT[Lab Technician\nForm Input] -->|POST /api/v1/blood-work\npatient_id, test_name, value, units, collected_at| Validate
    Validate[FastAPI\nRBAC check\nField validation\nNumeric precision check] -->|valid| Encrypt
    Encrypt[SQLAlchemy TypeDecorator\nAES-256 encrypt patient_id + value] -->|INSERT NUMERIC| DB[(blood_work_results\nPostgreSQL)]
    DB -->|SELECT with JOIN| Query
    Query[FastAPI\nGET /api/v1/blood-work/my-results\nPatient RBAC check\nJOIN reference_ranges on test_name\nCompute is_out_of_range] -->|decrypt PHI| Decrypt
    Decrypt[SQLAlchemy TypeDecorator\nAES-256 decrypt value] -->|JSON array| SPA
    SPA[React SPA\nRender results table\nAmber/red highlight if is_out_of_range\nWCAG AA contrast] --> Patient[Patient Browser]
```

## Sequence Diagrams

### User Login Flow

Shows the complete login sequence from form submission through credential validation, Argon2 verification, session creation, JWT issuance, and role-based redirect hint returned to the SPA.
```mermaid
sequenceDiagram
    participant Browser
    participant SPA as React SPA
    participant API as FastAPI /auth/login
    participant DB as PostgreSQL

    Browser->>SPA: Submit email + password
    SPA->>SPA: Client-side validation (required, email format)
    SPA->>API: POST /api/v1/auth/login {email, password}
    API->>DB: SELECT * FROM users WHERE email = ?
    DB-->>API: user row (password_hash, role)
    API->>API: Argon2 verify(password, password_hash)
    alt Invalid credentials
        API-->>SPA: 401 {message: "Invalid credentials"}
        SPA-->>Browser: Show inline error
    else Valid
        API->>DB: INSERT INTO sessions (token_jti, user_id, expires_at)
        DB-->>API: session created
        API->>API: Sign JWT {user_id, role, jti, exp: +8h}
        API-->>SPA: 200 {access_token, role, redirect_hint}
        SPA->>SPA: Store JWT in memory/sessionStorage
        SPA-->>Browser: Redirect to role dashboard
    end
```

### Lab Technician Submits Blood Work Record

Illustrates the data entry flow from Lab Technician form submission through RBAC validation, numeric precision storage, and success/error feedback. Covers US-005 and US-006.
```mermaid
sequenceDiagram

    participant SPA as React SPA
    participant API as FastAPI /blood-work
    participant DB as PostgreSQL

    LabTech->>SPA: Fill form (patient_id, test_name, value, units, collected_at)
    SPA->>SPA: Client-side validation (required fields, numeric value)
    SPA->>API: POST /api/v1/blood-work\nAuthorization: Bearer <JWT>
    API->>API: Validate JWT signature + expiry
    API->>API: Extract role from JWT claims

        API-->>SPA: 403 Forbidden

        API->>DB: SELECT id FROM users WHERE id = patient_id
        alt Patient not found
            API-->>SPA: 404 patient_id not found
        else Patient exists
            API->>DB: INSERT INTO blood_work_results\n(NUMERIC value, AES-256 PHI fields)
            DB-->>API: created record
            API-->>SPA: 201 {created record}
            SPA-->>LabTech: Show success confirmation
        end
    end
```

### Patient Views Blood Work Results

Shows the patient results retrieval flow including JWT role enforcement, JOIN with reference_ranges for out-of-range computation, and conditional formatting applied by the SPA.
```mermaid
sequenceDiagram
    participant Patient as Patient Browser
    participant SPA as React SPA
    participant API as FastAPI /blood-work/my-results
    participant DB as PostgreSQL

    Patient->>SPA: Navigate to My Results page
    SPA->>SPA: AuthGuard checks JWT validity
    SPA->>API: GET /api/v1/blood-work/my-results\nAuthorization: Bearer <JWT>
    API->>API: Validate JWT + extract patient_id and role
    alt Role != patient
        API-->>SPA: 403 Forbidden
    else Authorized
        API->>DB: SELECT bwr.*, rr.min_value, rr.max_value\nFROM blood_work_results bwr\nLEFT JOIN reference_ranges rr ON bwr.test_name = rr.test_name\nWHERE bwr.patient_id = <patient_id from JWT>
        DB-->>API: result rows with range data
        API->>API: Compute is_out_of_range for each row
        API-->>SPA: 200 [{test_name, value, units, min_range, max_range, is_out_of_range, ...}]
        alt No results
            SPA-->>Patient: Show 'No results found' message
        else Results present
            SPA->>SPA: Apply amber/red highlight to is_out_of_range rows (WCAG AA)
            SPA-->>Patient: Render results table
        end
    end
```

### User Logout with Back-Navigation Prevention

Covers the secure logout flow including server-side session invalidation, JWT removal from client storage, SPA redirect to login, and history.replaceState to prevent back-navigation to authenticated pages.
```mermaid
sequenceDiagram
    participant Browser
    participant SPA as React SPA
    participant API as FastAPI /auth/logout
    participant DB as PostgreSQL

    Browser->>SPA: Click Logout button
    SPA->>API: POST /api/v1/auth/logout\nAuthorization: Bearer <JWT>
    API->>API: Extract jti from JWT
    API->>DB: DELETE FROM sessions WHERE token_jti = <jti>
    DB-->>API: session removed
    API-->>SPA: 200 {message: "Logged out successfully"}
    SPA->>SPA: Remove JWT from storage
    SPA->>SPA: history.replaceState(null, '', '/login')
    SPA-->>Browser: Redirect to /login
    Note over Browser,SPA: Back button now shows /login\nAuthGuard blocks return to protected routes
```
