## Components

- **NavBar**: Top navigation bar displaying role-specific links and a logout button.- **LoginForm**: Form handling user authentication with email and password.- **BloodWorkTable**: Data table displaying patient blood work results with conditional formatting for out-of-range values.- **DataEntryForm**: Form for lab technicians to input patient blood work data.- **Button**: Reusable button component with variants.- **Input**: Reusable form input component with label and error state.- **Alert**: Feedback message component (success, error, warning).- **Badge**: Small status indicator, used for out-of-range highlights.
## User Flows

### Authentication and Navigation _(happy path)_
1. **LoginPage**: User enters credentials and submits → System authenticates, stores JWT, redirects based on role _(Patient -> /my-results, Lab Tech -> /data-entry)_2. **PatientDashboard**: User clicks Logout in NavBar → Session invalidated, JWT removed, redirected to /login _(Back navigation prevented via history.replaceState)_
**Error scenarios:**
- Invalid credentials show inline Alert on LoginPage
- Network failure shows generic error Alert

### Lab Technician Data Entry _(happy path)_
1. **LabTechDashboard**: Fills out DataEntryForm and submits → Data validated, sent to API, success Alert shown _(Form resets on success)_
**Error scenarios:**
- Missing fields trigger client-side validation errors on Input components
- API returns 422, mapping errors to specific Input fields
- API returns 404 for Patient ID, showing Alert

### Patient Views Results _(happy path)_
1. **PatientDashboard**: Page loads, fetches /api/v1/blood-work/my-results → BloodWorkTable renders with data _(Out-of-range rows highlighted with warning Badge)_
**Error scenarios:**
- No results returns empty array, table shows 'No results found'
- API returns 500, table replaced with error Alert
