## Risks

- **[CRITICAL]** PHI encryption at rest (AES-256) and in transit (TLS 1.3) must be correctly configured. Misconfiguration could expose patient data and violate HIPAA requirements, which is a critical compliance risk for a healthcare prototype.
  - _Mitigation:_ Explicitly specify encryption requirements in T-001 and T-007 schema tasks. Backend dev tasks (T-002, T-008, T-009) must enforce TLS at the transport layer. Include encryption verification as a mandatory acceptance criterion at the Sprint 1 and Sprint 2 gates.
- **[CRITICAL]** RBAC enforcement gaps: if the backend does not correctly validate the JWT role claim on every endpoint, a Patient could access Lab Technician endpoints or view another patient's data, violating the critical RBAC NFR.
  - _Mitigation:_ T-002 implements the JWT with role claim; T-008 and T-009 explicitly enforce role-based 403 responses. Role enforcement must be a mandatory acceptance criterion reviewed at the human gate for every backend task.
- **[HIGH]** Password hashing algorithm selection: using a weak or incorrectly configured hashing algorithm (e.g., MD5, SHA-1, or bcrypt with too-low cost factor) would fail the critical security NFR.
  - _Mitigation:_ T-002 specifies bcrypt or Argon2 explicitly. The human reviewer at the Sprint 1 gate must verify the algorithm and cost factor in the implementation before approving.
- **[HIGH]** Numeric precision loss for blood work values: floating-point storage in the database could silently corrupt lab values, causing incorrect out-of-range calculations and potentially misleading patients.
  - _Mitigation:_ T-007 specifies NUMERIC type (not FLOAT) for the value column. T-008 acceptance criteria include a data integrity check. T-009 returns the stored value without transformation.
- **[MEDIUM]** Sprint 2 has a high concentration of dependent tasks (T-007 → T-008 → T-010 and T-007 → T-009 → T-011). A delay in T-007 (schema) blocks all downstream Sprint 2 work.
  - _Mitigation:_ T-007 is the first task executed in Sprint 2 and has no Sprint 2 dependencies. Prioritize its completion in the first days of the sprint. Frontend tasks (T-010, T-011) can begin with mock API responses while backend tasks are in review.
- **[MEDIUM]** WCAG 2.1 AA compliance for dark-mode UI: conditional formatting colors (e.g., red/amber highlights for out-of-range values) may fail contrast ratio requirements against dark backgrounds if not carefully chosen.
  - _Mitigation:_ T-011 explicitly calls out WCAG AA contrast requirement for highlight colors. The design system established in the G4 design phase should provide pre-validated dark-mode color tokens. Frontend dev must verify contrast ratios using a tool (e.g., axe, Lighthouse) before submitting for review.
- **[LOW]** The reference ranges seed data (T-007) is hard-coded per the project assumption. If the seeded values are clinically inaccurate, the out-of-range highlighting in T-011 will be misleading.
  - _Mitigation:_ The open question regarding exact reference ranges should be resolved before T-007 is executed. If not resolved, use widely published standard ranges (e.g., from NIH/MedlinePlus) and flag the values explicitly in the code and documentation for human review at the gate.
